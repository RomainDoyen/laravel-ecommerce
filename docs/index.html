Documentation du projet e-commerce

Boutique en ligne avec catalogue, panier utilisateur, avis produits, commandes, informations de livraison et paiement via Stripe Checkout. Cette page décrit l’installation, la configuration et l’architecture du dépôt laravel-ecommerce.

Stack technique

Composant Détail
Framework Laravel 11
PHP 8.2 minimum
Base de données MySQL (sessions, cache et files en base possibles)
Front Blade, Tailwind (Vite), assets dans public/assets
Paiement Stripe PHP SDK + Checkout Session (stripe/stripe-php)
Abonnements (paquet) laravel/cashier présent dans composer.json (usage selon implémentation)
Tests Pest PHP

Installation

Prérequis

Composer, Node.js & npm, extension PHP pdo_mysql, serveur MySQL, compte Stripe (pour le paiement).

Étapes

# Dépendances PHP
composer install

# Fichier d'environnement
cp .env.example .env
php artisan key:generate

# Base de données : créer la base (ex. ecommerce) puis renseigner .env
php artisan migrate

# Optionnel : données de démo (rôles + utilisateurs)
php artisan db:seed

# Assets front (Vite)
npm install
npm run build   # ou npm run dev en développement
Santé de l’application : Laravel 11 expose une route GET /up pour les sondes de disponibilité.

Configuration (.env)

Variables courantes (voir aussi .env.example à la racine du projet) :

Variable Rôle
APP_KEY Obligatoire — généré par php artisan key:generate
APP_URL URL publique (ex. http://127.0.0.1:8000)
DB_* Connexion MySQL (DB_DATABASE, DB_USERNAME, etc.)
STRIPE_KEY Clé publiable Stripe (front / config services.stripe)
STRIPE_SECRET Clé secrète — utilisée côté serveur dans StripeController
SESSION_DRIVER Souvent database (tables sessions après migrations)
QUEUE_CONNECTION database si vous utilisez les files d’attente en SQL
MAIL_* Pour les e-mails (réinitialisation de mot de passe, etc.)

Base de données

Principales tables (déduites des migrations) :

Table Description
roles Rôles (libelle) — ex. Administrateur, Client
users Utilisateurs (nom, prenom, email, password, role_id)
categories Catégories de produits
produits Produits (titre, prix, category_id, stock, promo, image…)
carts Lignes de panier par utilisateur et produit
reviews Avis sur les produits
delivery_infos Coordonnées de livraison par utilisateur
orders Commandes (total, status, items JSON, order_number, lien livraison)

Modèles Eloquent

Role Liste des rôles
Produit belongsTo Category · hasMany Review
Category Catégories
Cart Panier (utilisateur ↔ produit, quantité)
Review Avis liés à un produit et un utilisateur
Order belongsTo User, DeliveryInfo
DeliveryInfo Infos de livraison

Seeders

Le DatabaseSeeder appelle RoleSeeder puis crée deux utilisateurs de démonstration via la factory. Les seeders CategoriesSeeder, ProduitSeeder et ReviewSeeder existent dans le projet mais ne sont pas invoqués par défaut — ajoutez-les dans DatabaseSeeder ou lancez-les à la main. 

# Tout le DatabaseSeeder
php artisan db:seed

# Un seeder précis
php artisan db:seed --class=CategoriesSeeder
php artisan db:seed --class=RoleSeeder

Comptes de démo (après db:seed)

Email Mot de passe Rôle
johndoe@gmail.com 1234 Client (rôle « Client » — role_id issu du seeder)
admin@test.fr admin1234 Administrateur (role_id = 1)
Important : changez ces identifiants en production et ne versionnez jamais de vrais secrets.

Préfixe /client

Connexion, inscription, espace perso, mot de passe oublié (routes nommées client.*).

Administration

Les routes /admin/dashboard, /admin/add, édition / suppression produit sont protégées par AdminMiddleware. La connexion admin reste sur /admin/login (hors du groupe middleware).

Espace client

  • Inscription — POST /client/register/post : affectation du rôle « Client » via le modèle Role.
  • Connexion — session Laravel ; redirection selon role_id (admin déconnecté s’il tente le portail client).
  • Panier — nécessite d’être connecté ; lignes stockées en base (carts).
  • Commandes — liste sur client.orders ; création possible via store_order avec livraison renseignée.
  • Livraison — formulaires création / édition des DeliveryInfo.

Administration

Accès au tableau de bord et à la gestion des produits pour les utilisateurs avec role_id === 1 (Administrateur). Connexion dédiée /admin/login.

Fonctions typiques : liste produits / catégories / commandes sur le dashboard, ajout et modification de produits (upload d’image, catégorie), suppression.

Paiement Stripe

Le contrôleur StripeController crée une Checkout Session en euros, à partir des articles du panier envoyés en JSON. Les URLs de retour sont checkout.success et checkout.cancel.

Définissez STRIPE_SECRET dans .env pour l’API serveur. La clé publique peut être exposée au front via STRIPE_KEY / config('services.stripe.key') selon votre intégration JavaScript. 

STRIPE_KEY=pk_test_...
STRIPE_SECRET=sk_test_...

Sécurité & rôles

Rôles

  • role_id = 1 — Administrateur (back-office, middleware admin).
  • Autre valeur (ex. « Client ») — accès front et espace client.

AdminMiddleware vérifie l’authentification et role_id === 1, sinon redirection vers l’accueil. Les actions sensibles dans AdminController redoublent parfois ces contrôles.

Structure utile du dépôt

app/Http/Controllers/     # Contrôleurs (Pages, Cart, Clients, Admin, Stripe…)
app/Models/                 # Modèles Eloquent
app/Http/Middleware/        # Ex. AdminMiddleware
database/migrations/        # Schéma SQL
database/seeders/           # Données initiales
resources/views/            # Vues Blade (front/, client/, admin/, checkout/)
routes/web.php              # Routes web
public/assets/              # CSS, JS, images statiques
docs/                       # Cette documentation (HTML statique)

Pour ouvrir cette documentation : fichier docs/index.html dans le navigateur, ou servez le dossier docs/ avec n’importe quel serveur HTTP statique.
